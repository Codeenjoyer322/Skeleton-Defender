## Проверка каталога

В Unity вызвать `SkeletonDefender.Editor.DirectionCoverageTests.Run`. Команда проверяет 344 обязательных вида: ходьбу и обычную атаку двух героев и 16 ролей врагов, восемь неподвижных видов жабы и шесть специальных действий врагов в восьми направлениях. Для выстрела и магии требуется событие выпуска с точкой запуска, для удара — контакт, для призыва — отдельное событие призыва. Неудачное заклинание содержит событие выпуска дыма. Событие, которое фактически выбирает модель, должно совпадать с нужным типом.

Разрешены общие кадры одного ракурса с явным `aliasOf` и собственными корректными событиями. Автоматическое отражение другого направления не считается готовым ракурсом. Обрезанные по прозрачным полям кадры проверяются в координатах полного холста через `sourceX/sourceY`; пиксели не растягиваются. Уникальные PNG не доказывают правильный вид лица, спины или оружия — это проверяется отдельно визуально.

Отчёт `work/animation-direction-coverage-results.json` сохраняет SHA-256 точного направленного каталога. Пока пакет неполный или отчёт относится к другой его версии, сценарий записи таблицы откажется публиковать результат.

## Подготовленная команда

Из корня проекта:

```powershell
& 'C:/Users/Life/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node.exe' 'work/animation-timings/build-timings.mjs' --update-080-final --dry-run
```

План сохраняется в `work/animation-timings/final-080-plan.json`. После успешной проверки того же каталога убрать `--dry-run`, чтобы обновить XLSX. Перед первой фактической записью таблицы используется обязательный маркер операции из навыка Spreadsheets.

Сценарий импортирует существующий файл, сохраняет старые строки каталога с отметкой заменённых клипов, добавляет направленные записи и перенаправляет формулы времени на актуальные восточные клипы. Другие направления доступны в каталоге. Пользовательские множители частоты, расчётное расстояние копья, игровые интервалы и остальные формулы сохраняются. Сценарий проверяет ошибки формул и выводит PNG изменённых областей для визуального просмотра.

Затем LibreOffice пересчитывает и преобразует новый XLSX в ODS во временной папке:

```powershell
& 'C:/Program Files/LibreOffice/program/soffice.com' '-env:UserInstallation=file:///C:/Users/Life/Documents/ChatGPT/Skeleton%20Defender/work/animation-timings/lo-final-080' --headless --convert-to ods --outdir 'work/animation-timings/final-080-ods' 'outputs/Тайминги анимаций.xlsx'
```

До замены опубликованного ODS сравнить имена листов, формулы, числовые значения и отсутствие ошибок с XLSX, просмотреть изменённые области, сохранить привычные настройки просмотра Calc. Резервная копия исходного XLSX находится в `work/animation-timings/before-final-080`. Старые режимы `--update-071` и создание таблицы с нуля для этой операции не использовать: они описывают предыдущую версию правил.

Окончательные количества записей, атласов и сумма декодированных пикселей берутся из `final-080-plan.json` после завершения пакета. Это оценка ресурсов RGBA32, не измерение полной памяти браузера.
